## 1. 이번 개정 요지

v1은 **7개 화면을 한 사이클에 다 만든다**는 전제로 쓰였고, 헤더/푸터 교체와 DB 스키마 확장이 착수 블로커로 박혀 있었다. v2는 두 가지 지시로 전제가 바뀐다.

1. **헤더/푸터를 이 브랜치 범위에서 완전히 제외.** 현행 `Header.jsx`(`fixed`, `h-[84px]`)·`SiteFooter.jsx`를 그대로 둔다. 시안의 64px 헤더·신규 푸터·로고 SVG는 `landing-renewal` 소관이다. → v1 §3.1-4(헤더 64px / `pt-16`)·§3.2-13(푸터 밴드)·§6(C) 로고 2건·결정 #22·Phase 0-2/0-3·리스크 R4가 전부 무효화되고, **`landing-renewal` 선행 머지 대기가 사라져 이 브랜치가 단독 진행 가능**해진다.
2. **1차 = 디자인 구현 / 2차 = 기능 구현.** 1차는 마크업·스타일·정적 렌더링·상태 전환(선택/hover/focus/disabled)까지. DB 스키마·응답 저장·채점 로직·PDF 생성·입시 마스터 데이터·관리자 연동은 전부 2차. → v1 §8 결정 23건 중 6건(#7·#8·#9·#11·#18·#21)이 2차로 이관되고, **채점 규칙 미정이 더 이상 리포트 착수를 막지 않는다**(더미 데이터 정적 렌더).

부수 결과로 v1에 없던 문제가 하나 드러났다 — 이 브랜치가 `/free-diagnosis`에서 legacy 무료진단을 걷어내 **DB 연동 퍼널이 dead code가 되어 있다**(§11).

### 4.1 헤더 오프셋 모델

`Header.jsx:598`은 `fixed`이고 **스페이서를 반환하지 않는다.** 본문 래퍼가 직접 상단 패딩을 가져야 한다.

시안의 "본문 상단 y"는 헤더 밴드를 포함한 페이지 최상단 기준값이다. 수집 문서가 이미 이 관례를 명시한다 — `survey-10656.md:378` "헤더 하단 ~ 본문 상단 = 120 − 64 = 56".

```
본문 최상단 pt = (시안 본문 상단 y) − (헤더 높이 H)
```

**구현: CSS 변수 1개로 상수화.** `landing-renewal` 머지 시 `4rem` 한 줄만 바꾸면 3화면이 자동 복원된다.

```css
:root { --wn-header-h: 5.25rem; }  /* 84px — 머지 시 4rem */
```

| 화면 | 시안 본문 상단 y | **H=84 (현행)** | H=64 (머지 후) | 클래스 |
|---|---|---|---|---|

시안에 992/990/1000/1058 4종이 혼재하고 척도 라벨 중심과 라디오 중심이 최대 8~9px 어긋나 있다. **원값 승계 시 시각적으로 더 나쁘다.**

## 11. 라우트·배포 리스크와 권장 대응

상세 [ROUTE-RISK.md](./ROUTE-RISK.md)

### 11.1 사실 확인

- `src/App.jsx:60-61`이 `/free-diagnosis`→`FreeDiagnosisLanding`, `/free-diagnosis/survey`→`SurveyPreview`로 교체됐고 `import FreeDiagnosis` 한 줄이 삭제됐다.
- `src/pages/FreeDiagnosis.jsx`(590줄)는 파일로 살아 있으나 **참조 0건**(`grep -rn "pages/FreeDiagnosis" src/` 매치 없음). 라우트 미등록 + `App.jsx:102` catch-all(`*` → `/` replace)이 미매치 경로를 삼켜 **404조차 뜨지 않는다.** → **어떤 URL로도 도달 불가한 dead code.**
- 형제 브랜치 `landing-renewal`의 `App.jsx:12,59`는 legacy를 **그대로 유지** 중. 걷어낸 것은 이 브랜치 단독.
- `SurveyProgress.jsx`에 **`onClick`이 없다.** 19문항을 다 채워 버튼이 활성색으로 바뀌어도 클릭 시 무반응, 새로고침 시 입력 전량 소실.
- `Admin.jsx:1621` `FreeDiagnosisAdmin`이 `free_diagnosis_*` 3테이블을 CRUD하는데 유일한 소비자를 잃어 **silent failure**(운영자가 문항을 고쳐도 반영 안 됨, 화면은 정상 동작처럼 보임).
- `public/robots.txt` **없음** (확인 완료).

### 11.2 결정적 제약 — `Header.jsx`를 건드릴 수 없다

`Header.jsx:112–132` `ensureFreeDiagnosisInService()`가 DB에서 온 nav든 캐시든 fallback이든(적용 지점 145·223·371) **무조건 '무료진단' 항목을 제거 후 `to: '/free-diagnosis'`로 강제 재주입**한다.
→ GNB 목적지는 관리자 DB로 변경 불가하고 **코드 편집이 유일한 수단**인데, 그 파일은 `landing-renewal`(48커밋)이 64px 헤더로 대대적으로 고치는 바로 그 파일이다. 건드리면 전제 A 위반 + 머지 충돌 확정.
→ 자동으로 "**`/free-diagnosis`는 계속 실제 서비스 가능한 페이지를 가리켜야 한다**"는 제약이 생기고, 1차가 미완성인 이상 그 페이지는 **legacy일 수밖에 없다.** 선택지가 (a)/(f)로 수렴한다.

### 11.3 권장 대응 — B1=(f)

```
/free-diagnosis                     → pages/FreeDiagnosis.jsx        (legacy 복원, 프로덕션 진입점)
/free-diagnosis/v2                  → renewal/FreeDiagnosisLanding   (신규 랜딩)

```

legacy에는 자식 라우트가 없어 `/free-diagnosis/v2`와 충돌하지 않는다(확인 완료).

**동반 조치 (필수)**

1. `/v2/survey` → `/v2/survey/1` **명시적 `<Navigate replace>`**. 없으면 `App.jsx:102` catch-all이 조용히 홈으로 삼키고, `replace`라 뒤로가기 복귀도 불가하다.
2. `:step` 유효성 검사 — 범위 밖이면 1스텝으로 리다이렉트.
3. `public/robots.txt` 신설 → `Disallow: /free-diagnosis/v2`. SPA라 per-route noindex는 별도 라이브러리가 필요해 과하다.
4. catch-all 자체를 404 페이지로 바꾸는 것은 **전역 동작 변경이라 이 브랜치 범위 밖**.

**2차 전환**: `/v2` 세그먼트 제거 → SPEC 최종 구조. 5스텝 라우팅·상대 링크·상태 보존을 1차에서 최종 형태로 검증하므로 라우팅 재설계가 없다.
