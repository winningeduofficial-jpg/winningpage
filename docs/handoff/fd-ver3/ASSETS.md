## 8. 사용자 결정 대기

1. **맥북 목업 구현 방식** — CSS 재현(landing.md 5.4 수치 확보) vs PNG @2x 추출. CSS 가 반응형·용량 유리하나 Shadow/Bottom 벡터 2개는 어느 쪽이든 필요.
2. **맥북 화면 콘텐츠 소스** — `2240:4597` 래스터 추출 vs 결과 리포트(A4-3) 컴포넌트 축소 렌더. 후자는 리포트 구현이 선행되어야 함.
3. **레이더 차트** — 래스터(`2226:2944`) 임시 사용 후 차트 컴포넌트로 교체 vs 처음부터 동적 구현. 시안이 축 순서·최대값·그리드 링 개수를 정의하지 않아 그대로면 스펙 미확정 상태.
4. **일러스트 3종 최적화 수준** — 현행 3.5 MB 원본을 @2x 로 줄이면서 WebP 전환까지 갈지, PNG 유지할지.
5. **Planet(`2181:11088`) 제외 정책 유지 여부** — ver2 사용자 지시로 제외했으나 ver3 시안에 여전히 존재.
6. **선택(selected) 상태 디자인 부재** — ver3 6화면 전체에 없음. `hero-browser-v2.png` 안의 스타일(연파랑 배경 + 파란 보더/텍스트 + 체크 아이콘)을 정본으로 채택할지 디자이너 확인 필요. 채택 시 `radio-checked.svg` 는 그대로 유지 가능.
7. **로고 SVG 교체 범위** — 헤더/푸터는 형제 worktree `winningpage-landing-renewal` 담당. `public/images/winning-logo.png`(불투명 배경) 교체를 어느 브랜치에서 할지 조율 필요.
